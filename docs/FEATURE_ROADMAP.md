# 赛题对照与下一阶段功能计划

依据本地《高云半导体.pdf》选题二，PDF第15～16页（印刷页13～14），以及《20260908嵌赛宣讲-高云半导体.pdf》第18～19页。此处为核对摘要，未公开上传原PDF；最终以赛事正式解释为准。

## 1. 赛题要求与当前差距

| 条目 | 原文要求摘要 | 当前证据/差距 | 行动 |
|---|---|---|---|
| 基础交互 | 自研交互、≥2独立可控维度 | TTP229已有，USB连接用户确认；普通键盘非力度传感器 | 保留自研触摸交互，提供独立音高/力度或表情控制；压力传感扩展更有说服力 |
| 音频计算 | 全部HDL逐样本逐声部计算 | 主工程为分音/相位/包络合成；USB微程序只做协议 | 音频通路代码佐证；协议UKP与禁止软核音频计算区分，必要时问组委会 |
| 总延迟 | ≤10ms | 未做端到端实测；TX35端点10ms轮询存在风险 | 同时测触摸和USB路径，统计最坏值/抖动/起音定义 |
| 复音 | ≥4独立声部同时发声 | 钢琴多实例；吉他6槽但单音池3槽，不能据6槽宣称任意4键独立复音 | 实测四个不同音；必要时统一动态池分配 |
| 基础合成能力 | 单音实时变调、ADSR、混音；禁录音触发 | 有固定音符参数和衰减包络；连续变调/可调完整ADSR尚未确认 | 补实时相位步进倍率和控制包络，逐条验收 |
| 扩展算力 | ≥32复音或单音≥32加法分量或多并行物理单元 | 吉他6槽×24分音，不能当作“每音32分量” | 稳定后按吞吐量与时序选择，不盲目扩槽 |
| 扩展表情 | ≥3维，力度动态、滑音、颤音等 | 部分演示有力度/闷音字段，完整键盘控制未接入 | 力度、连续音高、颤音三路可独立控制；评审统计口径需清晰 |
| 音色/效果 | ≥2乐器；FPGA内混响/延迟/合唱等 | 钢琴/吉他、清音/过载及吉他混响已有代码 | 键盘切换不误触发、响度和尾音回归；不把三种效果都列为已完成 |
| 拓展延迟/显示 | ≤5ms确定性延迟；FPGA视觉反馈 | USB轮询不宜承诺≤5ms；VOFA是PC绘图 | 硬件LED反馈可先做；波形/频谱硬件显示另列阶段 |
| 音频接口 | I2S到DAC | 当前PT8211串行格式需与标准I2S区别核对 | 查看DAC协议和赛题验收，不因能响就称已满足I2S |
| 联动扩展 | 脱机LED指引、手机曲谱等 | 演示事件表不等于完整LED教学；手机尚无 | 放在基础演奏之后 |

## 2. 推荐推进顺序

### P0：固定当前成功基线（现在）

保存本仓库源码清单；记录USB实际枚举、A按住/松开、KEY1独立发送。用户成功反馈不代替所有按键验收。
测试至少20轮按下/松开与5次插拔；不要求每次长音频仿真或全工程编译。

### P1：完整键盘事件层（映射审阅后第一步）

从8字节报告构造held bitmap及pressed/released差分；包含修饰键，忽略排列次序变化、重复报告不重复拨弦。
报告长度/类型检查、rollover处理、USB断连/超时清音、复位、热插拔。当前只会识别A，不能直接当作完整键盘驱动。
跨域采用稳定快照握手或异步FIFO，保证一份报告原子性；只读到一个A状态的两级同步不能替代此设计。
建立统一事件接口：source、note、press/release、velocity、mode、mute、expression，USB/TTP229进入同一调度器。
验收：四音和弦、四音+Shift/Ctrl、换序不重触发、快速交替、拔线不留长音；实测TX35矩阵冲突。若组合被键盘硬件吞掉，换组合或单键和弦，不伪造NKRO。

### P2：接已有音与基本演奏

按KEYMAP_PROPOSAL接16钢琴音和六弦；吉他先复用当前音色。明确按下/松开行为、力度锁存、同音重触发及声部抢占。
补任意四音复音验证：当前吉他单音池3路可能不够，优先重新分配现有6槽而非增加寄存器阵列。
确保F1/F2/F3/F4只切模式/效果，Space/Esc清掉正在等待的扫弦和替换请求。

### P3：先完善节奏手感

J/K上下扫与L齐奏，Q/W/E/R选和弦；扫弦次序与间隔、每弦相对力度、闷音包络分别控制。
建议从已认可的下扫8ms/上扫6ms起步，配强弱重音；这些是音色/演奏参数，不是USB延迟。
连扫时处理尾音重叠、总增益、过载前后增益，防止“轰鸣”和失真突然变弱。让暂停/制音无迟到音，保持相位和包络更新有序。

### P4：连续音高与滑音

先做一个主奏声部。每个音频采样更新目标pitch倍率或cents值，逐步逼近，保持相位累加器连续；不每步重新拨弦、不重置相位。
弯音是围绕原音高的可回中偏移；连奏滑音是从旧音到新目标；不能用离散换参数表冒充连续滑音。
建议对基准步进乘Q格式倍率，表/递推求倍率，目标在控制率更新、每采样平滑。所有谐波保持相对比例；高频分量越Nyquist需限幅或屏蔽。
先不插值整套音色/衰减表，锁存当前音色使音高连续可审听，再判断跨大音程是否需要音色过渡。
验收：慢滑与快滑频谱轨迹连续、起止准确、无爆音、不溢出、不破坏原声部；左右弯音释放回中。

### P5：颤音、力度和可调包络

V控制5～6Hz小深度音高LFO，初始±20 cents，深度和开关均平滑，允许与弯音组合。
小键盘力度是人工选择的velocity预设，左Shift是重音开关，不是按压力度传感。未来可加压力/滑条作为独立连续输入。
ADSR应有明确Attack/Decay/Sustain/Release参数及note-off行为；现有自然衰减/闷音不自动等于完整ADSR。钢琴延音踏板解除需释放已松键音，吉他普通拨弦可采用专属包络。

### P6：正式验收与展示

记录资源、setup/hold、每采样扫描周期、吞吐量。用不同频率四复音+频谱证据，不能仅看四个触发bit。
测物理触发到DAC音频起音的总延迟，USB和TTP229分开记录，多次取最坏值；10ms轮询本身不证明总延迟合格。
VOFA用于调试；FPGA原生LED/波形/频谱显示作为另一个独立功能。最后才考虑32分量/更多品位、手机和曲谱教学。

## 3. 资源与工程规则

新增音符参数≠增加同时声部；新增键位优先扩映射表。相位/幅度状态保留BSRAM和流水线策略。
音高倍率乘法按现有扫描时分复用，先估算再加DSP；不放宽时序或靠随机布局宣称解决。
测试按风险分层：先事件/单声部短仿真，再WAV试听/局部回归，RTL变更后必要的一轮编译。不要为文档或映射草案重跑整段曲子。

## 4. 本轮不实施的事项

所有新键位和上述功能只形成文档；用户确认KEYMAP_PROPOSAL后才修改RTL。现阶段不把整套USB自动并入主音频工程，不改已认可的音色参数。
